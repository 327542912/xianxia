# 接手手册：任何人 30 分钟能开工

> 这份文档写给下一位接手的人（也可能是三个月后的你自己）。读完它，你应该能：跑起验收、看懂世界怎么转、知道改一个规则该动哪几个文件、不踩已经踩过的坑。
>
> 配套文档：`制作流程.md`（怎么从需求走到发布）、`构建与发布.md`（怎么出 APK）、`验收与需求映射.md`（58 条验收对哪段代码）、`常见问题.md`（出错了先查这里）、`UI设计规范.md`（界面为什么长这样）。

## 一、这个项目是什么

一个**没有剧本的修仙世界仿真**：32×32 战略图上住着人、兽、草木；他们自己交易、结怨、结社、立宗、立国、分裂、崩解。你投生进去活一世，死后按生平出判词，再投下一世。时间只向前走，没有读档回退。

**不是什么**：

- 不是剧情游戏（没有写死的任务线）；
- 不是数值放置（所有结果由规则 + 随机 + 时间推出来）；
- 不是联网游戏（首版单机，但命令通道按可重放设计，将来可接服务器）。

## 二、三条铁律（违反就会把项目带歪）

1. **规则只在 `Assets/Scripts/Core/`，且不引用 UnityEngine。**
   内核必须能用 `dotnet` 单独编译、无头跑完 1500 年。呈现层（`Game/`、`UI/`）只读状态、只发命令。
2. **一切状态改变只走 `World.Act(verb, arg)`；时间只走 `World.Tick(1)`（1 Tick = 1 月）。**
   不许在界面里直接改 NPC 境界、灵石、洞府；不许用帧时间直接推年份。
3. **同一 seed + 同一串命令 = 同一 `StateHash()`。**
   不许用 `System.Random`、`DateTime.Now`、字典遍历顺序、浮点累加顺序来决定世界状态。要随机就用 `World` 内置的 xorshift64*。

## 四、10 分钟跑起来

只需要 .NET 8 SDK，不需要 Unity：

```bash
git clone https://github.com/327542912/xianxia.git
cd xianxia
dotnet run -c Release --project simcli -- 500
```

正常输出结尾是：

```
--- PASS 58 / FAIL 0 ---
```

看到 `FAIL` 会同时打印一行 `::error title=FAIL ...`，里面带该条目的实测数字，直接对照 `验收与需求映射.md` 查。

只想快速冒烟（约 3 分钟，仍能跑满 58 条）：

```bash
dotnet run -c Release --project simcli -- 200
```

长跑（CI 同款，20–40 分钟）：

```bash
dotnet run -c Release --project simcli -- 1500
```

## 五、六个必须懂的概念

1. **月制**：`Tick(1)` 推进一个月，`Year/Month` 是唯一时钟。行动也以月为冷却（`Act` 里“本月已行一事”）。所有年度概率都除以 12 摊到月。
2. **命令通道**：玩家的一切都是 `Act("meditate"/"help"/"open"/"flow"/"ascend"...)`。新增玩法 = 新增一个 verb，而不是在 UI 里加逻辑。
3. **`StateHash()`**：覆盖年份、NPC 的境界/体系/品阶/位置、小世界流速与不稳、世代链条数。改规则后哈希会变，这是正常的；但同版本同种子必须稳定。
4. **品阶**：凡/灵/神，横向乘数（修炼、寿元、战力），一生只能升一次，降阶不可逆，分解重炼是唯一重置（境界回退两境）。
5. **三套体系**：人（九境均衡）、兽（前快后慢、寿短）、草木（极慢、寿极长、不能移动）。`Cultivation` 一张表同时管内核与 UI。
6. **印象双账**：每个 NPC 对你有 `ImpDirect`（亲见）与 `ImpRumor`（传闻），有效值 = 亲见 + 传闻 × 放大（封顶 1.6 倍）。决定他是扶你还是杀你。

## 六、想改什么，去哪

| 你想改 | 动这里 | 别忘 |
|---|---|---|
| 新境界名/新寿元表 | `Cultivation.cs` | 同步 UI 的 `RealmName` 调用、加验收 |
| 新动词（玩法） | `Player.cs` 的 `Act` switch | 在 `Cultivation.CanAct` 加体系限制、在 `Hud.BuildDock` 加按钮 |
| 新势力/新经济规则 | `World.cs` 对应 `Step*` | 保持月度摊薄、加 `Put("xx", ...)` 验收 |
| 新小世界规则 | `Scale.cs` | 代价、不稳、崩解三件事必须同时成立 |
| 印象/声望规则 | `Impression.cs` + `Player.StepImpressions` | 亲见与传闻分开记，别再加单一 `Imp` 字段 |
| 判词/转世 | `Player.Die` + `Life.ArchiveLife` | 判词不露分数；世代链只增不改 |
| 界面版式 | `Hud.cs` + `UiKit.cs` | 先改 `Tok` 令牌，再改布局；禁止在面板里写死颜色 |
| 画面/相机/触控 | `WorldView.cs` / `GameApp.cs` | 保持三张网格、三个 draw call 的预算 |
| 构建/版本/签名 | `BuildAndroid.cs` + workflow | 版本号与 `VERSION` 环境变量一致 |

## 七、调试手册

- **复现某个世界**：`new World(seed)`。验收里固定种子 `42/7/123/999`，别改成随机。
- **看世界为什么变成这样**：`World.Log`（`AddLog` 写的编年史）、`Player.Journal`（你这一世的大事）、`W.Lives`（历代判词）。
- **怀疑不确定**：同一进程里 `new World(42)` 跑两次，比较 `StateHash()`。CI 第 22 条就是这个。
- **玩家卡住**：先看 `Player.ActedYear/ActedMonth`（月冷却），再看 `Cultivation.CanAct`（体系限制），最后看 `W.Walkable`（水/崖）。
- **UI 不刷新**：`Hud.Sync()` 由 `GameApp.Update` 每 0.25s 调；面板内容只在 `ShowTab` 或操作后重建（`_tabDirty`）。
- **Unity 层编译错误**：本仓库不能在无 Unity 环境编译 Unity 层；走 CI 或本机 Unity。已知坑见 `常见问题.md`。

## 八、禁做清单

- ❌ 在 `Core` 里 `using UnityEngine`；
- ❌ 在 UI 里直接改 `npc.Realm` / `Player.Stone`；
- ❌ 用 `System.Random`、`DateTime.Now`、`Guid.NewGuid()` 参与世界状态；
- ❌ 加“读档回到第 N 年”的入口（需求明确不可回溯）；
- ❌ 让玩家肉身被 `StepIndividuals` 自动移动（已修，别再打开）；
- ❌ 在 `Die` 里不判 `Player.Dead` 就重复封档（已修）；
- ❌ 给面板各写一套坐标/颜色（上一版丑的根因）；
- ❌ 提交 `Library/`、`Build/`、`*.csproj`、`*.sln`、`UserSettings/`；
- ❌ 把 Unity 授权、令牌、密码写进仓库任何文件。

## 九、30 分钟接手清单

- [ ] 跑通 `simcli 500`，看到 58/58；
- [ ] 打开 `docs/验收与需求映射.md`，随便挑 3 条，在代码里找到对应实现；

- [ ] 在 `simcli` 里加一条自己的验收（模板见制作流程），跑 200 年确认 PASS；
- [ ] 看一遍 `构建与发布.md`，确认你知道 APK 为什么需要 Unity 授权；
- [ ] 在仓库 Secrets 里确认 `UNITY_LICENSE` 是否存在（没有就先加，或明确“暂不出包”）。

做完这八项，你就可以安全地改这个项目了。
