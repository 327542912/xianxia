# 验收与需求映射（58 条）

> 一条验收 = 一个可判定的世界事实。`simcli` 跑 500 年 × 4 种子（42 / 7 / 123 / 999），CI 另跑 1500 年。
> 失败时终端会打印 `::error title=FAIL ...`，带实测数字；先对照本表的判据，再判断是产品错还是验收错。

## 一、怎么跑

```bash
bash tools/verify.sh 200    # 冒烟（58 条，约 3 分钟）
bash tools/verify.sh 500    # 全量
bash tools/verify.sh 1500   # 长跑
```

或直接 `dotnet run -c Release --project simcli -- 500`。

当前结果（2026-11-24）：

| 环境 | 年数 × 种子 | 结果 |
|---|---|---|
| 本机 .NET 8 | 200 | 58 / 58 |
| 本机 .NET 8 | 500 | 58 / 58 |
| GitHub Actions | 500 + 1500 | 58 / 58（运行 45382929663） |

## 九、已知的验收弱点

- 第 20 条只统计人族：草木/兽类寿元表不同，混入会失真（已在 `simcli` 里按 `Kind` 过滤）。
- 第 45 条已从“机制已接”的恒真断言改为确定性断言：死者账上有债主 → 来世落点在债主 2.5 格内；但样本仍是单点，不做统计显著性。
- 长跑 1500 年只在 CI 跑；本地跑 500 年。CI 失败时先看 `GITHUB_STEP_SUMMARY` 的完整输出。
