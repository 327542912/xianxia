# 制作流程：从一条需求到手机上能玩

> 这份文档规定“改动怎么做”。它不是建议，是门禁：任何一次规则改动，都要按这里的顺序走一遍。
> 目标：**验收不绿不出包，文档不更新不算完成。**

## 零、总览

```
需求（文档冻结）
   ↓
规则设计（Model → Cultivation/Grade → World → Player）
   ↓
验收先行（simcli 加条目 → 200 年冒烟 → 500 年全量）
   ↓
呈现与交互（WorldView → GameApp → Hud）
   ↓
构建（本地 Unity 或 GitHub Actions）
   ↓
真机验收（安装 → 首启 → 十条动线 → 性能）
   ↓
发布（tag + Release，源码与 APK 同一提交）
   ↓
复盘（更新文档 / 已知边界 / 路线图）
```

## 一、阶段 0：需求冻结

- 需求只认两份文档：`docs/需求文档-v1.0.md`（实施版）与 `docs/一世-需求v1.1.md`（融合稿）。
- **要改需求，先改文档，再改代码**；不许“代码先做了，文档回头补”。
- 文档里的 `【待定】` 不实现；`【已定】` 必须实现；`【推断】` 要先确认。
- 新增一条需求时，同时写下：验收方式（可测的数字/状态）、代价（性能/复杂度）、影响面（哪些旧验收会动）。

## 二、阶段 1：规则设计（只动 Core）

顺序固定，避免“数据没地方放就先写逻辑”：

1. **Model.cs**：加字段/类型。字段要带单位与口径注释（月/年、km²、0..100）。
2. **Cultivation / Grade**：如果是体系或品阶的横向规则，放这两张表，不要散落在 World 里。
3. **World.cs**：加 `Step*` 结算。要求：
   - 按月摊薄（年度概率 ÷ 12）；
   - 只改世界状态，不碰 UI；
   - 重要事件写 `AddLog`，玩家相关写 `Player.Journal`；
   - 需要随机时用 `_rng` / `_rngImp`，不许 `System.Random`。
4. **Player.cs**：如果是玩家可做的事，加一个 `Act` 分支 + `Cultivation.CanAct` 限制 + 日志文案；能付代价的先付代价（折寿/材料/声望）。
5. **Life.cs**：如果影响死亡/转世/存档，更新 `ArchiveLife` / `StateHash` / `SaveSnapshot`。

> 判定标准：写完 Core 后，`dotnet build` 必须过，且 `simcli` 能跑（哪怕新条目还没加）。

## 三、阶段 2：验收先行

### 3.1 加一条验收（模板）

在 `simcli/Program.cs` 的对应区块里：

```csharp
// 59 一句话说清这条验收在保证什么
var w59 = new SimCore.World(2026);
w59.BeginLife();
var p59 = w59.PlayerNpc;
p59.Realm = 3; p59.Lifespan = p59.Age + 1200;

bool ok59 = /* 可判定的条件，别用“看起来对” */;
results["59 条目标题"] = ok59;
details["59 条目标题"] = $"关键数字={...}";
```

硬要求：

- **一条验收只判一件事**，标题写成人话；
- 判据必须是**状态/数字/集合**，不能是“随机跑跑看”；
- 失败时 `details` 要能直接定位（打出实际值）；
- 不为了让验收变绿去改阈值/改数据；先判断是产品错还是验收错。

### 3.2 跑的顺序

```bash
dotnet run -c Release --project simcli -- 200   # 冒烟：新条目 + 明显回归（58 条）
dotnet run -c Release --project simcli -- 500   # 全量：4 种子
dotnet run -c Release --project simcli -- 1500  # 长跑：机制不能只在前 500 年成立
```

三条全绿才算规则完成。**任何一条 FAIL，不进阶段 3。**

### 3.3 常见的“验收绿了但产品坏了”

- 只用单个种子通过 → 必须 4 种子；
- 只在 200 年通过 → 必须 500/1500；
- 玩家相关机制只在 Bot 里成立 → 要在真实 `Act` 链路上验；
- 改了 UI 但没跑内核 → UI 只读，不应影响验收；若影响，说明你在 UI 里写了世界。

## 四、阶段 3：呈现与交互

顺序：**WorldView（画什么）→ GameApp（怎么动）→ Hud（怎么点）**。

- **WorldView**：只读 `World`。地形/地物/人物各一张网格，仍是 3 个 draw call；新增地物要合并进 `_propMesh`，不要每件一个 GameObject。
- **GameApp**：新增交互先走 `DoAct(verb)`；相机/寻路/选中都在视图层，不写世界。
- **Hud**：先改 `Tok` 令牌（颜色/字号/间距），再改布局；一个面板只做一件事；弹层一次只开一个；可点区域 ≥ 88px。
- **文案**：面向玩家的一句话，动词开头，不露内部字段名与分数。
- **性能**：新增每帧逻辑前先问“能不能 0.25s 一次”；新增网格前先问“能不能并进现有网格”。

## 五、阶段 4：构建

- 首选 GitHub Actions：推 `main` 即跑验收；授权存在则自动出 APK 并发 Release。
- 本地构建：需要 Unity 6000.0.85f2 + Android Build Support；命令见 `构建与发布.md`。
- **构建前必须确认**：`ProjectSettings/ProjectVersion.txt` 的版本与 workflow 的 `UNITY_VERSION` 一致；`Packages/manifest.json` 没被手工改坏。
- 构建失败按 `常见问题.md` 的“构建失败排查”走，不要连点重跑。

## 六、阶段 5：真机验收（十条动线）

安装后按顺序走，任何一条不通过都不发布：

1. 首启 3 秒内能进地图，不黑屏、不卡死；
2. 自动投生，人物卡显示姓名/体系/境界/品阶/寿元；
3. 点地面能寻路走过去，点小人能选中并出现人物条；
4. 修行能推进进度，突破有提示；
5. 行善/拒人/夺灵各一次，事件条与人物印象变化；
6. 洞府/入宗各一次，卷宗里能看到对应信息；
7. 开辟小世界，再改流速，能看到折寿与不稳上升；
8. 升品一次（成功后按钮应拒绝第二次）；
9. 等待到死亡，判词页完整，能再入轮回；
10. 连续玩 5 分钟，帧率稳定、发热可接受、无 UI 重叠。

## 七、阶段 6：发布

1. 版本号：`0.7.x` 规则修，`0.8.0` 新玩法，`1.0.0` 首个稳定版；`ProjectVersion` 不动，只动 `VERSION`。
2. 更新 `README.md` 的“当前版本/验收结果/已知边界”。
3. 打 tag 或直接推 `main`（workflow 会发 `v{VERSION}` Release）。
4. Release 说明必须写：引擎与版本、新增规则、验收结果、APK 签名方式、安装条件（ARM64 / Android 8+）。
5. 发完在手机上装 Release 里的 APK 复核一次（不要只信 CI）。

## 八、阶段 7：回滚与兼容

- 代码回滚：`git revert`，不要 force push；回滚后重跑 500 年验收。
- 规则回滚：改回规则会让 `StateHash` 变，旧存档摘要不再匹配——这是**预期行为**，不要做“兼容旧档”的假回退。
- 存档策略：当前只有摘要（seed + months + hash）；将来做真实存档时，**仍然不提供回到过去**，只提供“从当前月继续”。
- 发布回滚：Release 可删可重发，但已安装的 APK 不会自动降级；版本号必须递增。

## 九、每次改动的 10 项检查表

- [ ] 需求文档已更新（或确认无需更新）
- [ ] Core 不引用 UnityEngine
- [ ] 随机只走 `_rng`，无 `System.Random` / `DateTime.Now`
- [ ] 新规则有月度摊薄与日志
- [ ] 新动词有 `CanAct` 体系限制与 UI 入口
- [ ] `simcli` 新增/更新了对应验收，`details` 有实测数字
- [ ] 50 / 500 / 1500 年全绿（至少前两项本地跑过）
- [ ] 面板不重叠、触控 ≥ 88px、颜色只来自令牌
- [ ] README 的版本与验收数字已更新
- [ ] 没有提交构建产物、缓存、密钥

## 十、分工建议（多人时）

| 角色 | 负责 | 交付物 |
|---|---|---|
| 规则 | `Core/` + `simcli` | 验收全绿 + 规则说明 |
| 呈现 | `Game/` | 三条动线可玩 + 帧率记录 |
| 界面 | `UI/` | 版式与令牌一致 + 真机截图 |
| 发布 | workflow + 文档 | Release + 安装验证记录 |

规则与呈现可以并行，但**规则未过 500 年验收前，呈现层不接新字段**，避免返工。
