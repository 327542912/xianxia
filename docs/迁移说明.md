# 从 Godot 到 Unity：迁移与构建说明

## 一、为什么换

- 你要求改用 Unity，并把源码与安装包一起发到 GitHub。
- 旧版（Godot 4.7.2 mono）完整保留在 `legacy/godot-game/`，可对照、可回退查看；`main` 根目录现在是 Unity 6 工程。

## 二、目录对照

| 旧（Godot） | 新（Unity） | 说明 |
|---|---|---|
| `legacy/godot-game/SimCore/Model.cs` | `Assets/Scripts/Core/Model.cs` | 数据模型，新增体系/品阶/印象来源/法宝字段 |
| `legacy/godot-game/SimCore/World.cs` | `Assets/Scripts/Core/World.cs` | 世界演化，全部保留 |
| `legacy/godot-game/SimCore/Player.cs` | `Assets/Scripts/Core/Player.cs` | 一世循环与命令通道，新增升品/炼宝/改流速/重炼 |
| `legacy/godot-game/SimCore/Scale.cs` | `Assets/Scripts/Core/Scale.cs` | 世界节点，新增流速代价、不稳与崩解 |
| `legacy/godot-game/scripts/Main.cs` | `Assets/Scripts/Game/*.cs` | 呈现层重写（地形/人物/相机/触控） |
| `legacy/godot-game/scripts/UI.cs` 等 | `Assets/Scripts/UI/*.cs` | 界面重写（令牌/组件/HUD/卷宗/判词） |
| `simcli/` | `simcli/`（引用 `../Assets/Scripts/Core/*.cs`） | 无头验收，验的就是同一份规则源码 |
| `tools/build_apk.sh` | `Assets/Editor/BuildAndroid.cs` | CI 构建入口 |

## 三、架构

```
SimCore（纯 C#，零引擎依赖，可 dotnet 跑）
   ↑ 只读/命令
Unity 呈现层（WorldView 地形与人物；GameApp 时钟相机触控；Hud 界面）
```

- 所有状态改变只走 `World.Act(verb, arg)`；`World.Tick(1)` 按月推进。
- 画面不写世界状态；选中、缩放、寻路都只是视图层。
- 世界哈希 `StateHash()` 覆盖年份、NPC 境界/体系/品阶、小世界流速与不稳、世代链长度。

## 四、新增玩法（需求 v1.1 落地）

| 条款 | 落点 | 可测证据（见 `simcli` 49–58） |
|---|---|---|
| 品阶凡/灵/神，一生一升、可单向降、分解重炼唯一重置 | `Grade.cs` | 升 1 成功、升 2 拒绝、降阶后仍锁、重炼归凡 |
| 功法/法宝品阶受创造者与材料封顶 | `Grades.Cap` / `CraftTreasure` | 改良本不高于底本；凡手神料仍为凡品 |
| 人·草木·兽三套境界与寿元表 | `Cultivation.cs` | 草木 1098 年 > 人 180 年 > 兽 142 年 |
| 草木扎根、兽不通人间礼法 | `Cultivation.CanAct` | 草木不可移动/入宗；兽不可入宗 |
| 小世界开辟与自定义流速必须有代价 | `Scale.cs` | 开界折寿、改流速涨不稳、过猛崩成遗府 |
| 第一印象：亲见≫转述≫传闻，重复传播放大有上限 | `Impression.cs` | 亲见 30 vs 传闻 1.9；30 次传播封顶 1.6 倍 |
| 每一世开局在洪荒早期 | `Life.cs EraAt/FindPrimordialCell` | 落点方圆五格无组织香火、地脉未破 |
| 世代链只增不改、存档无回退入口 | `Life.cs` | 死后封档 1 条，存档只有 seed/months/hash |

## 五、构建与发布

### 5.1 需要的 Secrets

| Secret | 用途 |
|---|---|
| `UNITY_LICENSE` | Unity 授权文件（.ulf 内容，推荐） |
| `UNITY_EMAIL` / `UNITY_PASSWORD` | 或者用 Unity ID 在 CI 激活 Personal 授权 |

在 `Settings → Secrets and variables → Actions` 添加。未配置时流水线会**跳过构建并给出 warning**，验收仍照跑。

### 5.2 流水线

`.github/workflows/unity-android.yml`

1. `acceptance`：.NET 8 跑 `simcli 500` 与 `1500`（58 条，全绿才继续）；
2. `license`：检查授权 Secrets；
3. `build`：`game-ci/unity-builder@v4` → `Xianxia.EditorTools.BuildAndroid.Build` → `Build/xianxia.apk`；
4. 上传 artifact，并在 `v{版本}` 标签发布 Release（源码与 APK 同一提交）。

### 5.3 本地构建

```bash
# 需要 Unity 6000.0.85f2 + Android Build Support（SDK/NDK/JDK）
Unity -batchmode -quit -projectPath . \
  -executeMethod Xianxia.EditorTools.BuildAndroid.Build \
  -buildTarget Android -logFile build.log
# 产物：Build/xianxia.apk
```

构建时自动完成：生成最小场景 → 竖屏/ARM64/IL2CPP/GLES3/minSdk 26 → 关闭阴影与抗锯齿 → 尝试创建 URP 资产（失败退回内置管线）→ 出包。工程里**不提交** `.unity` 场景与 `PlayerSettings.asset`，避免手写 YAML 的 GUID 错位。

## 六、已知边界（诚实清单）

- 本环境无法安装 Unity（官方 CDN 不可达），Unity 层**未经本地编译**；首次 CI 构建可能暴露 C# 编译错误，需要按日志修一轮。内核层已在本机编译并 58/58 通过。
- 安装包为调试签名（个人测试用），未做正式上架签名；如需上架要补 keystore。
- 渲染是程序化低模 + 顶点色，无美术资产、无角色动画骨骼（人物为几何体组合）。
- 未做音频、存档写盘（存档摘要接口已在 `SaveSnapshot`，尚无 UI 读档；且按设计不提供回退）。
- 10 万在册是「个体 + 统计层凡人」口径；L0 详细个体仍为几十人规模，四层 LOD 未实现。
- 旧 Godot 版仍在 `legacy/`，不再维护；`main` 的 CI 只产出 Unity 包。
