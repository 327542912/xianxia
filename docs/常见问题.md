# 常见问题与已知边界

> 先查这里，再动手。每条都是这个项目真实碰到过的问题，不是通用清单。

## 一、构建 / 出包

### Q1：Actions 里 `Unity Android 构建` 显示 skipped，是不是构建坏了？

不是。流水线先跑 `检查 Unity 授权`，没有 `UNITY_LICENSE`（或邮箱密码）时输出 `has=false`，`build` 被 `if` 条件跳过，验收照跑。加授权后 `Re-run all jobs` 即可。

### Q2：为什么不能在这台机器/我的虚拟机里装 Unity 直接打包？

三个硬条件：

1. **授权**：Unity 编辑器无论装在哪，batchmode 构建前都必须激活许可证；沙箱没有 Unity 账号。
2. **资源**：编辑器解压 7–8 GB + Android 模块 + SDK/NDK ≈ 12 GB+；本沙箱只有 9.3 GB 可用、3.8 GB 内存（IL2CPP 建议 16 GB）。
3. **下载**：实测 `download.unity3d.com` 与 `download.unitychina.cn` 对 6000.0.84f1 / 6000.0.85f2 / 2022.3.62f3 均返回 **404 NoSuchKey**，拿不到安装包。

GitHub runner 本质也是虚拟机，但预装了 Unity 与 Android SDK，资源也够，所以它是可行路径。

### Q3：`UNITY_LICENSE` 怎么填？

`Settings → Secrets and variables → Actions → New repository secret`，Name 填 `UNITY_LICENSE`，值粘贴 `.ulf` 文件全文（XML 原样）。文件位置：

- Windows `C:\ProgramData\Unity\Unity_lic.ulf`
- macOS `/Library/Application Support/Unity/Unity_lic.ulf`
- Linux `~/.local/share/unity3d/Unity/Unity_lic.ulf`

### Q4：用邮箱+密码激活失败？

账号开了两步验证（2FA）时基本会失败；改用 `.ulf`。

### Q5：构建报 C# 编译错误怎么办？

在 `构建 APK` 日志里搜 `error CS`。已修过的坑：

- `Tok.Font` 属性与 `Font` 类型同名 → 类内 `Font` 被解析成属性，编译失败；现改名 `Tok.UiFont`。以后不要在 `Tok` 里再加与类型同名的成员。
- 自绘材质写 `material.color`，但着色器没有 `_Color` 属性 → 日志报错；现全部走顶点色。
- Unity 6 的 `PlayerSettings.SetApplicationIdentifier` 需要 `NamedBuildTarget`，旧 `BuildTargetGroup` 重载有警告/弃用。

### Q6：APK 装不上？

- 只打了 **ARM64**：很老的 32 位手机会装不上；
- 最低 **Android 8.0（API 26）**；
- 调试签名，部分手机管家会提示“未知来源”，允许即可；
- 包名固定 `com.xianxia.yishi`，同包名不同签名不能覆盖安装，先卸载旧包。

### Q7：构建时间多久？

首次 20–40 分钟（无 `Library` 缓存），之后 10–20 分钟。`concurrency` 已配置，同分支重复推送会取消上一次。

## 二、运行 / 玩法

### Q8：点地面人物不动？

- 草木之身不能移动（`Cultivation.CanMove`）；
- 目标格是水/崖（`World.Walkable`）；
- 你正处在“本月已行一事”的冷却里（`Player.ActedYear/ActedMonth`）——行走不耗月，但其它行动耗。

### Q9：为什么这个月按什么都没反应？

月制冷却：一次行动 = 一个月。按钮会变灰；点「待月」推进一个月，或等世界时钟（1× 下 30 秒 = 1 月）。

### Q10：面板/文字看不清？

- 界面按 1080×1920 参考分辨率设计，`CanvasScaler` 匹配 0.5；极端长屏（21:9）上下会有留白，这是预期；
- 字体是随包的 CJK 字体；若出现方块，说明 `Assets/Resources/Fonts/NotoSansSC-Regular.ttf` 没被打进包或被裁剪，检查 `Resources` 路径与打包日志。

### Q11：帧率不到 60？

先确认不是在编辑器里跑（编辑器本身开销大）。真机排查顺序：

1. 是否开了实时阴影/后处理（构建脚本应已关闭）；
2. 是否新增了每帧网格重建或每帧控件创建；
3. 是否把地物拆成了大量 GameObject（应合并进 `_propMesh`）；
4. 是否在 `Update` 里做了字符串拼接/排序/全表遍历。

### Q12：能读档回到上一年吗？

不能，这是设计：时间单向不可逆。现有存档只有摘要（seed + months + hash），没有回退入口。将来做真实存档也只提供“从当前月继续”。

### Q13：判词里为什么没有分数？

需求明确：判词只出四档断语，不露分数。分数只在内部用于决定来世（善者为人，恶者为草木禽兽）。

### Q14：小世界流速调不上去 / 一调就崩？

- 只能改自己的世界（`node.OwnerId == npc.Id`）；
- 每次改流速都折寿，并累加不稳；不稳到 1 就崩成遗府；
- 这是“必须有代价”的条款，不是 bug。

## 三、验收 / 开发

### Q15：`simcli` 报 FAIL，但我觉得规则是对的？

先看 `details` 里的实测数字，再对照 `docs/验收与需求映射.md` 的判据。常见原因：

- 只跑单种子（验收要求 4 种子：42/7/123/999）；
- 年度概率没除以 12；
- 改了随机顺序（插入一次 `_rng` 调用会让后续世界全变，属正常，但要接受哈希变化）；
- 玩家相关机制在 Bot 路径里没走到。

**不要**为了让检查变绿去改阈值、改数据、删断言；先判断是产品错还是验收错。

### Q16：为什么改了规则后 `StateHash` 变了？

哈希覆盖年份、NPC 境界/体系/品阶/位置、小世界状态、世代链条数。规则改动导致世界不同是预期的；同版本同种子必须稳定（第 22 条验的就是这个）。

### Q17：`dotnet: command not found`？

安装 .NET 8 SDK（<https://dotnet.microsoft.com/download/dotnet/8.0>）。CI 用 `actions/setup-dotnet@v4`。项目不需要 Unity 就能跑内核验收。

### Q18：能直接用 `System.Random` 吗？

不能。它的实现跨 .NET 版本不保证一致，会破坏“同种子同世界”。用 `World` 的 xorshift64*。

## 四、已知边界（诚实清单）

1. **Unity 层未在本地编译**：本环境无 Unity，只做了 Roslyn 语法扫描与 API 人工审查；首次 CI 构建可能还需修一轮编译错误。
2. **APK 尚未产出**：缺 Unity 授权 Secret，构建被跳过。
3. **未做真机验证**：UI 实际观感、触控热区、60 帧都需装包后复核。
4. **美术是程序化低模**：几何体组合 + 顶点色，无手绘资产、无骨骼动画、无粒子。
5. **无音频**。
6. **存档只有摘要**：`SaveSnapshot()` 返回 seed/months/hash，没有 UI 读档；按设计不提供回退。
7. **10 万在册是统计口径**：个体 + 统计层凡人；L0 详细个体仍为几十人，四层 LOD 未实现。
8. **验收第 45 条只验单点**：已从“机制已接”的恒真断言改为确定性断言（死后债主记档 → 来世落点在债主 2.5 格内），但仍不做统计显著性。后续可扩成多世样本。
9. **旧 Godot 版不再维护**：`legacy/godot-game/` 仅供对照，CI 不再出 Godot 包。
10. **发布用调试签名**：上架需补 keystore 与 AAB 流程。

## 六、遇到文档没写的问题

按这个顺序：

1. 在 `docs/` 里搜关键词；
2. 看 `World.Log` 与 `Player.Journal`，确认世界到底发生了什么；
3. 用固定种子写一个最小复现（`new World(42)` + 几个 `Act`），贴到 Issue；
4. 修完把结论补进本文件“已知边界”或对应文档，别只留在聊天记录里。
