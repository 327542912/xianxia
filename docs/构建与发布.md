# 构建与发布：从源码到可安装 APK

> 结论：**GitHub Actions 是首选路径**。它本质是一台云端虚拟机（约 4 核 / 16 GB / 14 GB SSD），`game-ci/unity-builder` 镜像里已预装 Unity 与 Android SDK；你只需要提供 Unity 授权。
> 本机/自建虚拟机也能构建，但需要 ≥16 GB 内存、≥30 GB 空闲磁盘，并能登录 Unity 账号激活。

## 一、三条路对比

| 路径 | 需要什么 | 耗时 | 适用 |
|---|---|---|---|
| GitHub Actions（推荐） | 仓库 Secrets 里的 Unity 授权 | 首次 20–40 分钟，有缓存后 10–20 分钟 | 日常出包、发布 |
| 本机 Unity | Unity 6000.0.85f2 + Android Build Support + 授权 | 10–20 分钟 | 调试画面、真机联调 |
| Docker（GameCI 镜像） | Docker + 授权文件挂载 | 20–40 分钟 | 无 Unity 授权的服务器 |

## 二、Unity 授权（唯一硬门槛）

Unity 编辑器在 batchmode 构建前必须先激活许可证；**装在哪台机器都一样**。仓库需要一个 Secret，三选一：

### 方式 A：`UNITY_LICENSE`（推荐，最稳）

1. 在任意一台装了 Unity Hub 的电脑登录 Unity 账号，激活 **Personal**（免费）许可证；
2. 找到许可证文件：
   - Windows：`C:\ProgramData\Unity\Unity_lic.ulf`
   - macOS：`/Library/Application Support/Unity/Unity_lic.ulf`
   - Linux：`~/.local/share/unity3d/Unity/Unity_lic.ulf`
3. 仓库 → `Settings → Secrets and variables → Actions → New repository secret`
   - Name：`UNITY_LICENSE`
   - Secret：把 `.ulf` 文件的**全文**粘进去（XML 原样，不要改编码、不要加引号）。
4. 触发一次 workflow（推提交或 `Run workflow`），`检查 Unity 授权` 应输出 `has=true`。

> `.ulf` 里含机器绑定信息，但 GameCI 的激活流程支持在容器内使用；不要把它提交进仓库。

### 方式 B：`UNITY_EMAIL` + `UNITY_PASSWORD`

加两个 Secret，GameCI 会在构建时自动激活 Personal 授权。

- 优点：不用找文件；
- 限制：账号开启两步验证（2FA）时通常失败；企业/组织账号也可能被策略拦截。失败就改用方式 A。

### 方式 C：`UNITY_SERIAL`（Pro/Plus/企业）

加 `UNITY_SERIAL` + `UNITY_EMAIL` + `UNITY_PASSWORD`。个人项目一般用不到。

### 授权缺失时会发生什么

`license` 任务输出 `has=false`，`build` 任务被 `if` 跳过，验收照跑。这是**预期行为**，不是构建坏了；摘要里会提示缺哪个 Secret。

## 三、CI 流水线

文件：`.github/workflows/unity-android.yml`

```
push/tag/manual
   ↓
preflight：仓库自检（必需文件、manifest JSON、版本一致性、Core 无 UnityEngine 引用）
   ↓
acceptance：.NET 8 跑 simcli 500 与 1500（58 条，全绿才继续）
   ↓
license：读 Secrets，决定是否构建
   ↓
build：game-ci/unity-builder@v4 → Xianxia.EditorTools.BuildAndroid.Build
   ↓
artifact + Release（v{VERSION}，APK 与源码同一提交）
```

### 版本号

- 默认 `0.7.0`；打 tag `v0.8.0` 时自动用 tag 名；
- 手动触发可填 `version` 输入；
- `BuildAndroid` 把它写进 `PlayerSettings.bundleVersion`，`BUILD_NUMBER` 写进 `versionCode`。

### 手动触发

`Actions → unity-android → Run workflow`：

- `version`：留空用默认；
- `long_run`：是否跑 1500 年长跑（默认 true，赶时间可关）。

## 四、本地构建

### 4.1 环境

- Unity Hub 安装 **6000.0.85f2**（必须与 `ProjectSettings/ProjectVersion.txt` 一致）；
- 勾选 **Android Build Support**（含 SDK/NDK/JDK）；
- 激活许可证（Hub 登录即可）。

### 4.2 命令

```bash
# macOS
/Applications/Unity/Hub/Editor/6000.0.85f2/Unity.app/Contents/MacOS/Unity \
  -batchmode -quit -projectPath "$PWD" \
  -executeMethod Xianxia.EditorTools.BuildAndroid.Build \
  -buildTarget Android -logFile build.log

# Windows（PowerShell）
& "C:\Program Files\Unity\Hub\Editor\6000.0.85f2\Editor\Unity.exe" `
  -batchmode -quit -projectPath "$PWD" `
  -executeMethod Xianxia.EditorTools.BuildAndroid.Build `
  -buildTarget Android -logFile build.log

# Linux
~/Unity/Hub/Editor/6000.0.85f2/Editor/Unity \
  -batchmode -quit -projectPath "$PWD" \
  -executeMethod Xianxia.EditorTools.BuildAndroid.Build \
  -buildTarget Android -logFile build.log
```

产物：`Build/xianxia.apk`。日志里搜 `[Build] result=`。

也可以直接用仓库脚本：

```bash
UNITY_BIN=/path/to/Unity bash tools/build_android.sh
```

### 4.3 构建脚本自动做了什么

`BuildAndroid.Prepare()` 在出包前统一设置，避免仓库里手写 YAML：

- 生成 `Assets/Scenes/Main.unity`（空场景，运行时由 `GameApp.Boot` 自举）；
- 写入 `EditorBuildSettings`；
- 包名 `com.xianxia.yishi`、竖屏、ARM64、IL2CPP、GLES3、minSdk 26、Linear 色彩；
- 关闭实时阴影/抗锯齿/像素灯（60 帧预算）；
- 尝试用反射创建 URP 资产并挂到 `GraphicsSettings`；失败自动退回内置管线（着色器是管线无关的）；
- 版本号与 versionCode 从环境变量读。

## 五、Docker 构建（可选）

```bash
docker run --rm -v "$PWD":/project -w /project \
  -e UNITY_LICENSE="$(cat Unity_lic.ulf)" \
  unityci/editor:ubuntu-6000.0.85f2-android-3 \
  unity-editor -batchmode -quit -projectPath /project \
  -executeMethod Xianxia.EditorTools.BuildAndroid.Build \
  -buildTarget Android -logFile /dev/stdout
```

镜像较大（数 GB），首次拉取慢；适合没有 Unity 的构建机。

## 六、签名与上架

当前是**调试签名**：`useCustomKeystore = false`，手机可直接安装，适合个人测试与 GitHub Release。

要上架（Google Play / 国内商店）需要：

1. 生成 keystore（`keytool -genkeypair`），保存密码与别名；
2. 把 keystore 转 base64 放 Secret（如 `ANDROID_KEYSTORE_BASE64`）、密码放 `ANDROID_KEYSTORE_PASS` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASS`；
3. 在 `BuildAndroid.Prepare()` 里设置 `PlayerSettings.Android.useCustomKeystore = true` 与 `keystoreName/keystorePass/aliasName/aliasPass`（或用 GameCI 的 `androidKeystoreName` 输入）；
4. 出 AAB（`buildAppBundle: true`）而不是 APK。

> 不要把 keystore 与密码提交进仓库。

## 七、构建失败排查（按顺序）

1. **`Unity Android 构建 skipped`** → 没有授权 Secret。按第二节加，然后 `Re-run all jobs`。
2. **`has=true` 但构建报 License 错误** → `.ulf` 内容不全（换行丢失/复制了路径）；重新复制全文。2FA 账号改用 `.ulf`。
3. **C# 编译错误** → 点开 `构建 APK` 日志搜 `error CS`。已知坑：
   - `Tok.Font` 属性遮蔽 `Font` 类型（已修，别再加同名属性）；
   - 自定义着色器缺 `_Color` 却写 `material.color`（已去掉）；
   - `PlayerSettings` API 在 Unity 6 改名（用 `NamedBuildTarget`）。
4. **IL2CPP 被 OOM 杀** → runner 内存不足或并行构建；减少并发、提高 runner 规格、关掉 `long_run` 省内存。
5. **Gradle/SDK 报错** → 确认 `minSdk 26`、`targetSdk auto`、只有 ARM64；GameCI 镜像自带 SDK，别在 workflow 里手工装版本冲突的 SDK。
6. **下载 Unity 404 / 超时** → 你所在网络到 `download.unity3d.com` 被拦。用 GameCI 镜像（已预装）或换网络；本仓库不在 CI 里下载 Unity。
7. **产物找不到** → 构建方法把 APK 写在 `Build/xianxia.apk`；workflow 会 `find -name '*.apk'` 收集，检查日志是否有 `[Build] result=Succeeded`。

## 八、成本与时间

- 公开仓库的 Actions 分钟数免费；私有仓库按套餐计。
- 首次构建没有 `Library` 缓存，20–40 分钟；缓存命中后 10–20 分钟。
- 建议 `concurrency` 取消同分支重复运行，省时间也省额度（workflow 已配置）。
